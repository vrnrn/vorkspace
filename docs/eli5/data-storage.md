# Saved data

All runs open your existing desktop database, kept in your Mac's Application Support folder, by default so your work and chats persist across restarts. If the launcher leaves out your home folder, the app finds it through your Mac account. An isolated sandbox database is used only if you pass `--dev-data`. Your settings come from the app's own settings file; conversation text and agent session IDs stay intact.

Use `--check-data` to check a selected database without writing to it. Unsent messages, cursor selections, attachments and MCP tags reopen from the same saved draft. Edits are saved while typing and flushed when the view closes or the app quits. If two windows edit the same draft, neither silently overwrites the other. The conflicting input stays saved separately and appears with a preview when you reopen the chat, so you can choose which version to keep. Once you choose, that banner goes away. A Bot send can keep a saved receipt until it is safely queued, so a crash does not send the same message twice. Missing attachments stay recorded so sending cannot silently drop them. Vox also keeps its saved enabled, silent and microphone choices.

Bot memories stay in the Bot's folder inside the data folder, and the app edits them there. A Bot that used to belong to a project keeps that project's folder, and an empty newer folder does not hide it.

Adding a Bot opens a setup form with the name field ready to type. You must give it a name and press Create before it is saved. Cancel leaves no new Bot or chat behind. Its chosen model, permissions and soul stay saved while its chat is being prepared, including if the app closes during that preparation. Existing Bots keep their names and chats.

When an agent adds text, the app saves the changed part of the chat instead of copying all the old tool output again. Older chats switch to this storage when they are first saved successfully. Opening a database just to check it does not change its format.

Before using this faster saving method, the app prepares the storage needed for queued messages, Bot drafts, delivery claims, local send records, notes, to-dos, and automations. If an unrelated database change happens, the next save checks the saved messages and continues when they match. Changes made by another writer still receive the usual protection. When the app opens, automations look up unfinished runs directly. The app also saves a record of old trigger events once so the same event cannot start another run. Very old automations kept their single trigger in a different place. The first time automations open, the app copies the whole database into a private `backups` folder next to it, checks that the copy opens, and only then updates those automations to the current format. If the copy fails, nothing is changed.

Saved tool details stay intact even when the screen shows only a short preview. If another window changes the same conversation during a local turn, the app reloads the saved conversation in place and keeps the competing version under **Recovered versions**. Your unsent draft stays in the composer. If saving the competing version fails, you can still copy it or retry while the app is open. A failed save leaves the previous saved chat and message receipts together.

Before sending locally, the app saves a record of the message. If the connection breaks or the app stops, it does not assume the agent did nothing and send the message again. Unconfirmed messages stay available to review. You can explicitly put a copy back in an empty composer. Dismissing the notice does not permit an automatic repeat.

When you pick a different provider, the app saves the choice and the old provider’s conversation together. You can switch back to the same conversation before the handoff starts. If you pick another provider while a reply is finishing, that reply can only finish its own handoff. Your previous model settings are read from the existing settings file until the app saves them with the conversation.

Pasted pictures stay in a private attachment folder. The app makes sure a file is saved before sharing its path. A background check can remove old pictures that no saved message or draft uses. If another app process is using the folder, saved data changes, or the check cannot finish safely, it leaves the pictures alone. A read-only data check never cleans attachments.
