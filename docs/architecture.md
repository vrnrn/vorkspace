# Architecture

## Desktop ownership

`crates/vorkspace-gpui` owns windows, focus, layout, input, rendering, and interactive views, on top of the smaller `vorkspace-ui`, `vorkspace-runtime`, `vorkspace-editor`, `vorkspace-model`, and `vorkspace-macos` crates. `crates/vorkspace-core` owns provider transports, persistence, filesystem/Git operations, account configuration, Bot state, and application effects. These app owners execute in one desktop process. Optional [Codebase Memory](codebase.md) runs a pinned local engine in a private subprocess namespace; the desktop core remains the authority for project access and cancellation.

`vorkspace-editor` analyzes source independently of the window framework. Tree-sitter and the bounded QuickJS fallback publish byte ranges and compact semantic token kinds. Embedded parser class names decode at that boundary, including a plain-text fallback for unknown styles. The desktop resolves the resulting classes through the live theme.

Text layout caches key wrapped geometry by text, font runs, font size, width and remaining line limit. Unwrapped shaping remains reusable independently of wrapping. Frame retention transfers only validated layout ranges, and font generation changes invalidate both frame caches.

Native workspace and editor menu commands share the ordinary action dispatch path. If AppKit has deactivated the window, the remembered workspace retains its focused control as the action target. Management dialogs keep their own focus and reject underlying editor commands.

Formatting starts a fresh bounded interpreter with Prettier's language and option catalog. Parser and printer code loads on demand from six compiled-in plugins, including plugins needed by embedded languages. Find delegates query, word-boundary and replacement policy to CodeMirror's SearchQuery. Asset builds compare native formatting against the full upstream Prettier entry point. The PHP bundle applies guarded lexer and heredoc-highlighting corrections at generation time.

A conversation admits a turn, records its submission state, starts the selected provider CLI through the core process owner, and projects streamed events into the visible transcript. Approvals and Stop remain routed through that owner. Durable receipts and revision checks distinguish accepted work from unknown or stale results. Closing or hiding a view does not mean its conversation was deleted.

The core owns the session database and reads and writes its SQLite schema directly. Native viewport and supplementary state live in an atomically written `.gpui.json` sidecar. Bot files live under the selected data directory. History projection preserves unloaded fields and canonical provider session IDs; conflicting writes fail instead of replacing newer state. [Data continuity](data-storage.md) explains historical-data reads.

Startup prepares the saved window layouts, workspace definitions, and Bot roster before creating windows. AppCore owns the immutable definition snapshot and stages changes through the shared settings writer. Its session directory stores one record per conversation, with the summary, checkout binding, and saved draft marker together. Windows read the same records and keep their own selection, panes, focus, and list order. A live conversation has one window lease. A prepared conversation enters the directory when its owner installs it. Opening another window reconciles newly read saved records against the directory while preserving live or pending edits.

AppCore merges shared preference edits against the settings each editor saw. It publishes the result once and applies the affected app-wide configuration, including menu, shortcut and helper settings. Picker choices enter through the same owner and settings writer. Each window applies its own interface scale and updates its open views.

AppCore shares one reminder schedule and one linked GitHub feed across workspace windows. Reminder writes publish in order and target the saved occurrence by session and due time. A single deadline handles known reminders, with periodic reconciliation for changes written outside the app. macOS authorization and click callbacks wake their consumers directly. Each window owns the placement and focus of its notification controls.

Delegated sessions inherit explicit execution settings from their source. Orchestration workers stay private during preparation. The originating run must still own a starting assignment before the app publishes its conversation. A stopped or superseded run discards its private preparation.

## Rendering and history work

Markdown exposes one semantic paragraph across shaped prose and inline code layouts. Contiguous text for the same link shares one accessible target with its original URL, shaped bounds and direct activation action. Text siblings preserve reading order. Geometry and action registration are produced only while the accessibility adapter is active.

Indexed histories are projected one source block at a time. Complete local loads read display rows, historical turn metadata, and the exact revision in one SQLite snapshot. Durable tool payloads remain in storage and display metadata excludes large output fields. Preference-only writes skip historical turn projection. Window activation refreshes visible chats. The inactive cache retains reconstructible transcripts within its budget and releases an oversized transcript without displacing the rest of the warm set. Drafts and pending work keep their history pinned.

Active standalone indexed Bot chats initially retain the newest ten turns when older indexed history exists. Older pages load off the UI thread, retain the reading anchor, and carry global row offsets for saved-search reveal. A page cursor is tied to the table owner, block contents and positions, and turn boundaries in one SQLite snapshot; a changed snapshot restores the complete history, while a transient failure leaves the cursor available for retry. Transcript mutations and Bot execution restore the complete history first. Page-relative core writes independently validate the snapshot in the merge transaction, preserve unloaded blocks, and allow appends only through the newest page; they invalidate complete-history readers' write guards. The page API scans the full indexed history to validate the snapshot and calculate row offsets, so it bounds retained page rows but not read or projection work. Blob and ordinary histories use their existing loading paths.

Streaming persistence writes changed blocks against a guarded durable revision. Ordered history rows separate large immutable payloads from frequently updated session metadata. The core store owns database transactions, including submission receipts; a GUI projection cannot replace unloaded fields. See [incremental history writes](data-storage.md#incremental-history-writes).

The provider runner separates child execution and settlement from wire decoding. Codex command chunks update a bounded UTF-8 output tail. A batch publishes the latest tool snapshot at the position of its first chunk, then the transcript persists the resulting rows. A parked child retains only the continuation needed for reuse with the same binding and launch choices.

Bot card refreshes use an application-owned persistence worker. Admission coalesces each card without taking the database lock; the worker compares the captured card with its durable block by ID and changes only that metadata. It preserves external references, opaque fields, message boundaries and later history. Warm revision guards advance only across this owner’s commit. Fixed-size card-content guards independently reject stale card rows even after subsequent provider tail saves, until authoritative history reload. Cold digest guards retain only the owning blocks changed locally until the next history load or save, so a provider tail save can validate those exact changes without accepting external edits or stale card rows. The submission generation rejects outdated fetches before admission. Successful receipts reconcile into the matching session, save version, card identity and current value even if a new submission has started. Failed or conflicting saves keep the old visible value and release admission for a later refresh. Navigation or view disposal does not cancel admitted writes. Application quit closes admission and awaits draining within GPUI's existing 200 ms asynchronous cleanup budget; neither the quit callback nor worker-owner destruction joins a storage-blocked thread. Process exit before commit can lose an unpublished cosmetic refresh intent; the previous durable value survives and can be refreshed on the next launch.

A transcript view owns one elapsed-time task while it is visible and streaming. Settled prose shares the same layout path as live prose and releases its pacing buffers when the reveal finishes. Transcript edits update the display index from the first changed row. The prompt outline uses the list's logical scroll position to find nearby prompts.

Attachment thumbnails share two decode slots across windows. A thumbnail owns its queued task, and an active worker holds its slot until the read and decode finish. The transcript cache bounds retained thumbnail data separately. Full-screen image previews have an independent loading path.

The [terminal](terminal.md) uses statically linked libghostty-vt for VT state and key encoding, with GPUI drawing the grid and a Unix PTY owning the shell. Terminal grids stay current when hidden. Repaint-only signals are coalesced before they reach the UI queue, while ordered PTY, clipboard, and exit effects are preserved.

The title bar and Changes panel share one immutable snapshot per checkout. One local porcelain observation supplies the dirty paths, index identities, working-copy file stamps, branch and upstream. An unchanged observation reuses the previous snapshot without recalculating line counts. An active local checkout watches the working directory and its Git metadata directories through macOS file events. A change wakes the Git status probe, and a sustained event burst is limited to one probe every two seconds. The checkout also reconciles every 20 seconds and accepts explicit refreshes. Paths without a watch use polling. History panes share a lazily loaded commit graph in the same checkout cache. The checkout refreshes History on commit or branch changes and periodically reconciles other refs while History is visible. Windows retain their own search, selection, and scroll. The graph model produces typed geometry and the desktop paints it. Review resolves its Git context once per load and publishes file completions together as they arrive. Review anchors the viewport to the file and row the reader was on. Folded context retains its line count. A staged hunk uses the byte ranges captured for the displayed diff. A file tab identifies its Git side, including for deleted files. Discard checks the displayed change after confirmation and surfaces failures in the pane. Local commit review compares a merge with its first parent and scopes paths to the selected project. Changes retains ordinary commit-message drafts by checkout while the panel is open. Confirmations are tied to the checkout and branch tip where they started.

Recorded turn review reads the selected path from the two saved Git trees for the turn that opened the tab. Undo and Keep target the checkpoint shown on the card, and the checkpoint owner rejects a superseded target. Structured edit evidence belongs to the active checkpoint ID. The checkpoint writer keeps its temporary index and metadata private and publishes the completed review after both trees are saved.

The runtime turn registry admits one worker per shared store handle and session. Its RAII guard belongs to the execution worker through the final save, including manual compaction and unwind. The desktop driver separately registers the weak conversation view and projects ordered updates. An admitted run keeps draining updates if its view disappears, while an unattached read-only observer retires. Projection cleanup checks the exact token before removing a registration, preserving any successor. **View → Running Work** and the pressure indicator open the app-wide list of local provider processes. Stop uses the sampled turn's cancellation capability across windows and remains available through the runtime when its view is gone. A warm provider can retain its PID across distinct turn capabilities.

Process usage is a derived observation. If enumeration fails, verified provider roots retain their exact-turn Stop controls while CPU, memory and descendant counts remain unavailable. Tool termination still revalidates current process birth and live ancestry before signaling.

Automation execution belongs to one Service per canonical database, protected by a stable private advisory-lock file beside that database. Other app processes can edit definitions and queue requests. The executor alone recovers orphaned work and claims pending requests as preparing. Store creates a fresh session, its settings and automation metadata in the same writer transaction as the running receipt. The executor validates the database and expected run identity before that transaction publishes. The desktop retains installation ownership during preparation and awaits the running receipt before submitting to a reused conversation. It revalidates checkout and reused-view ownership after the await. Preparing work can return to the queue after an executor handoff. Interrupted running work remains cancelled and retains its linked conversation for inspection. A preparation failure after publication also retains that conversation. Terminal receipts reject stale state changes.

Each admitted run carries the identity, attachments and one-time options of its source. Composer sends consume their own attachments. Queued messages and Bot dispatch use the options captured with the message. These paths leave a separate composer draft available for the user's next action.

Side questions save drafts and transcripts under their parent conversation, with their own read-only provider runs. The visible sheet projects only its selected thread. Switching or dismissing the sheet releases that projection while other side threads retain their rows and drafts. Saves compare the revision they loaded so a window with an older copy cannot overwrite newer side questions.

Bot chats keep their configured face and name in a fixed overlay within the transcript viewport. The existing conversation status drives idle, working and attention states, with attention taking precedence. A Bot is drawn in two parts: its body (shape, colour and printed pattern) is rasterized once per look and pixel size into a byte-budgeted cache, and its face, gaze, blink, hop and squash are drawn over it each frame as vector quads and paths. A pose therefore never rasterizes an image, and pointer gaze in the settings preview moves only the vector face. The header shares the body cache but has no pointer-tracking input. Each avatar pose reports when it next changes, and the owning view is woken only then. Idle life is a sparse choreography on a window-wide 4 s beat: on some beats a Bot glances to a new look or blinks, moving for at most 300 ms on a shared 33 ms frame grid, and then holds its pose without intermediate frames until the next beat that changes it. Any number of idle avatars, across views, therefore share at most about a dozen frames per beat. Sidebar gaze keeps cursor state per window and invalidates its rendering owner when the pointer enters, moves within, or leaves the rail; the settings preview follows pointer events and blinks on the same beats. Visible working and attention avatars tick on the same frame grid. Each window and rendering owner keeps only its earliest pending wake; a sooner wake cancels and supersedes a later one. Bot bodies and color swatch images live in byte-budgeted least-recently-used caches. Evicted images remain pinned while a retained view still references them. Once no scene uses an image, its atlas tiles are released across windows; visible images may temporarily exceed the cache budget. On macOS, paired native group markers fade transcript content around the face back to the already-rendered background, preserving its colors, texture and transparency. The radial feather composes with the transcript's edge fade and stays outside composer and attention controls. Decoration does not intercept chat input, and hidden or clipped content and inactive windows suppress automatic animation frames. The empty-chat greeting contains help text rather than a second face.

The expanded rail starts with the [vorkspace](vorkspaces.md) switcher and, below navigation and Bots, a Sessions section across the vorkspace's projects; it no longer lists projects. The collapsed icon rail follows the same order: the vorkspace mark, navigation, every Bot in the vorkspace, and a Sessions button (dotted while a session works or has an unseen reply) that expands the rail. It has no project picker or sidebar-tab buttons; the top bar's sidebar toggle owns those. It also keeps the Working card: it projects running, approval-blocked and unseen finished sessions across projects from Shell's existing session state. It appears above Subscriptions when at least one session qualifies and opens sessions through the normal navigation owner. General settings keep its visibility preference. The card initially shows four sessions, with an accessible More/Show less disclosure into a height-bounded virtual list. Each row shows the project-marked title, latest actual tool or approval/completion status, and provider/project/duration metadata. Runtime tool events publish a bounded label through a dedicated conversation notification; ordinary tokens and tool output do not rebuild session discovery. A missing tool falls back to Working. Elapsed-time updates stay within the card's presentation; those ticks do not load history or rebuild the session snapshot. The timer stops when the card cannot display elapsed time. The card observes window bounds and preserves its top session across row reordering and compact-layout changes. Navigation shares the upper rail scroller so short windows retain access to the card disclosure, resources, subscriptions and Settings.

The workspace owns one tab order and one `PaneNode` split tree per tab. Sessions, detached files, Bots, terminals, Search, Notes, connector pages and items, Automations, To-dos, and Bot documents share that tree. An app pane has a durable typed descriptor and an opaque layout ID; it never creates a synthetic session or passes its ID into the conversation store. Existing session and file layouts retain their identities. Legacy standalone Bot and terminal tabs migrate into the same tree without reopening stale focus references. Closed descriptors reserve their IDs so a delayed event cannot target a successor.

Shell owns the live view for each open resource. Each note and connector item gets an independent editor or reader, pinned to its semantic identity. Opening that resource again focuses its existing pane. Moving a pane, changing focus, and switching tabs preserve its entity, draft, scroll and in-flight work. A note selected in the library transfers its existing editor and recording edit lease into the pinned pane; the library then routes that note to its existing tab. Inbox pages share the root polling authority but own their selection, comments and detail scroll. Closing a view does not cancel a previously admitted durable save or remote action.

Picking a project in the sidebar header's picker or in Search, or switching vorkspace, always shows that project: it leaves a visible Bot pane and opens the project's focused session, even when the Bot belongs to that project or was its last focused tab. Programmatic reselection of the current project keeps a visible Bot and its open editors.

Files opened from app panes use a review pane scoped to the project and working copy. Its live editors retain drafts when the workspace tab closes. Its saved review state restores the files and working copy after restart. A new file pane from a Bot link opens to the right of that Bot when it fits, or in its own tab. The pane keeps that Bot as its Add to chat destination through moves, reopening and restart. A diff comment stays in its editor until the destination composer accepts it. Each Bot pane hosts the linked GitHub activity for its own visible chat.

A visible file editor observes its own checkout for Git baseline changes and checks its local file revision before reading the body. The local revision includes file identity, size and both modification and status-change times. Saving still compares the exact disk bytes. A save cancels publication from an older pending read, and a reload applies its discard decision to the draft present when it started.

The existing layout engine handles mixed panes: drag a tab to an edge to tile its entire layout, drag a split header to move one pane, or drag it to the strip to detach it. The same 420-point minimum column width, three-content-pane vertical limit and sash bounds apply. Detached file panes retain their existing vertical-limit exemption. Oversized saved layouts remain scrollable, and moves may reduce their overflow. Every visible leaf remains active; keyboard commands and the composer follow the focused leaf. Bot document list clicks open a pane to the right of the Bot when it fits, otherwise a separate tab. Each Bot pane owns a floating Documents island. It stays visible while the pane fits both the normal 832-point chat column and the 316-point island lane; narrower panes show a small top-right trigger, and clicking that trigger or the Bot face opens the island as an overlay. Selecting a resource dismisses the compact overlay without moving the Bot conversation. The island opens Bot settings, where Habits are managed; Bot-specific diff browsing is not shown. Closing a Bot presentation preserves its runtime, draft and running work.

`vorkspace-ui/src/radius.rs` owns the logical-point corner scale: 4 for small controls, 6 for standard controls and tabs, 8 for inset content, 12 for panes/cards/menus, and 16 for dialogs and the Bot island. Renderers use the same token for surface fills, borders, hover states and clipping; nested outlines subtract their border and padding inset. AppKit retains native window geometry. Circular controls, icon artwork and notch contours keep their own shapes. The custom AppKit clipboard menu follows the same scale. See [DESIGN.md](../DESIGN.md) for surface conventions.

Rail rows and title tabs use separate rounded backgrounds for hover and selection, with no animated joins to the pane. Shared theme controls own tab fills and sizing; the rail divider follows the adjacent pane’s 12-point corners independently of selection. Tab opening, closing and reordering retain their existing motion settings. Explorer, Changes and To-dos sit between the rail and the workspace on the left; sessions are listed in the rail. Legacy `sidebar_right` preferences are ignored. In compact rail mode, the rail and navigation strip share the shell background without an added divider. [Project to-dos](todos.md) have To do, In progress, In review and Done states, descriptions, attachments and dependencies. Bots operate assigned project boards; they do not have separate boards. Local boards work without a connector, with optional explicit GitHub issue publication and reconciliation.

Archiving a project hides its idle scoped tabs and refuses while its conversations run or terminals remain open. Deleting a project selects another project first and applies the existing resource ownership checks before removing data. Settings retains its section navigation and shared page controls.

Command-clicking the title strip's **+** opens and focuses a new terminal tab for the selected local project or worktree directory; a plain click and ⌘T open a session. `shell/terminal_tabs.rs` retains one `Terminal` entity per stable terminal-tab ID, independently of its starting directory and the project's dock entities. Multiple tabs in the same directory have separate shells, output and close ownership; clicking an existing title tab selects that exact shell. Selecting another tab hides the grid without terminating its PTY or changing its cwd. Terminal tabs share title-tab selection, drag order, close menus, and workspace persistence; only identity and starting cwd are saved, with a fresh shell created on first selection after restart. Legacy cwd-only saved tabs acquire IDs before order deduplication, with scope focus mapped to the corresponding tab. Explicit close checks the foreground process, asks before closing a running job, and releases the entity through `Terminal::drop` (PTY shutdown and Unix shell/process-group hangup). Hidden tab output updates its grid without observing or notifying Shell. Existing dock menu commands and shortcuts remain available and own separate shells.

Parked provider leases are removed under their pool lock, then destroyed after releasing it. Cancellation epochs prevent a settling cancelled lease from reappearing after its binding is invalidated.

Provider transports admit encoded output before growing their buffers. A single encoded provider event frame is limited to 128 MiB; each transport shares a 256 MiB allocation budget across frames being read, queued, and processed, with at most 16 queued frames. A full budget applies backpressure; an oversized frame fails explicitly instead of being truncated. Closing the receiver wakes blocked producers before their threads are joined. These limits cover encoded transport buffers, not the provider subprocess or parsed conversation state.

Interface scale is limited to 60%–160% and uses a per-window GPUI transform, separate from display DPI. The window maps platform input and text-input geometry to the same logical layout used for rendering and accessibility. Native HTML and video hosts convert their clipped bounds at the platform boundary; changing scale invalidates cached paint geometry.

Cached GPUI views record the frame that owns their drawing ranges. Replaying an ancestor can relocate a nested view without updating that nested view's cache. If the ancestor later renders without caching, as during a sidebar transition, the nested view rebuilds any ranges that do not belong to the immediately preceding frame. Rebuilding preserves the view's entities and interaction state; unchanged caches still replay normally.

## JavaScript boundaries

- Editor analysis and formatting run committed bundles in bounded QuickJS interpreters. Their time limits count the interpreter thread's CPU time, so a busy machine cannot interrupt them. Rust owns files, edits, and saves.
- Vox runs a Rust controller that owns its Codex app-server child, bounded tool receipts, saved conversation identity, memory, and shutdown. An ephemeral WebKit WebRTC page handles microphone and audio only. Window-scoped GPUI handlers admit actions through existing session and Bot owners.
- Claude sessions routed through Copilot use a Rust loopback gateway. The supervised Claude process owns its gateway across parked turns; terminating that process releases the listener and connected clients. Other provider transports remain Rust-owned local CLI processes.

JavaScript is maintained directly under `embedded/`. No browser frontend or TypeScript compilation step is part of the application build.

## Platform services

GPUI renders the desktop, including Notes, its recordings, and Markdown previews. WebKit hosts the Vox audio surface and opaque HTML artifact previews. The artifact WebView has no app message handler. Sparkle can verify and install explicitly configured macOS updates.

Notes, Automations, Inbox, Todos and Search share the sizing and controls in `controls/page.rs`; [native page design](native-pages.md) defines the scheme. Note text and recording summaries share `markdown::Document`, while Inbox retains its measured document owner and uses the same prose styling. Narrow navigation retains the selected document and its editing state.

A session keeps its own worktree. `worktree_management` assesses removal, and `Shell::remove_worktree` handles requests from Settings and app actions so open views update either way. It resolves the path Git registered, then holds a guard that keeps new turns and terminals out during removal. Agents use Git's non-force removal and require verified safety checks. Uncommitted or unique work, ignored files outside regenerable folders such as `target` and `node_modules`, and unarchived sessions block cleanup. After confirmation, Settings can discard a worktree with a named branch once Git verifies it is unlocked. If other safety checks fail, the branch is kept. Detached worktrees require a complete, safe assessment. With complete evidence, Git can remove a fully merged branch along with its worktree.

A project's setup command is configured in the user's preferences. Worktree creation records the selected command in the application's private setup directory, keyed to the linked checkout's identity. Older setup records under Git metadata require manual review. The first turn working there runs it with a 10-minute limit. Stop or quitting the app ends a running command. A failed or interrupted command leaves a warning for ordinary prompts until the provider confirms completion of a turn that carried it. Overlapping turns and uncertain delivery can repeat the warning.

Close to Tray hides the one workspace window instead of quitting, and clicking the Dock icon brings it back. It needs the menu bar icon, so it falls back to quitting when the icon is off.

Bots are opened inside the main workspace. The macOS menu bar opens clipboard history, also available with ⌘⇧C. General settings control the icon and contain a Clipboard group between Workspace and About. The clipboard menu offers New meeting above Settings and Quit; it opens a new note ready to record. During capture, Stop recording replaces New meeting; Quick Composer retains its separate global shortcut.

Clipboard history and ⌘⇧C belong to `vorkspace-helper`, which can outlive the app. It ships as a nested `vorkspace helper.app` with its own bundle identifier so the Dock can launch the main app independently. The app runs the helper while clipboard history or dictation is enabled, or while a note is capturing or finalizing a recording. Each installed helper has an owner-only Unix socket scoped to its path. Control messages, recording events and transcript text cross the socket. Clipboard contents stay in the helper. A file lock gives each socket a single helper, and each helper serves one app at a time.

When clipboard history and dictation are off and no recording is active, the main app owns the menu bar icon if enabled. Clicking it brings the workspace back. The panel's Quit goes through the app's unsaved-file prompt when the app is open, stops the helper if the quit goes ahead, and otherwise just exits. Settings, New meeting and the notch’s Open meeting action open the app first when it is closed and are delivered once it connects, using the launch command and arguments the app sent on connect, so a reopened app keeps its data selection. A Clear pressed during a reconnect is delivered when the connection returns. The helper reports its binary's modification time on connect. Replacing it after an update or rebuild clears history. Logging out also clears history, and clipboard recording resumes when the app next opens.

Clipboard history has one owner in the helper process with at most 50 entries and a 64 MiB retained payload budget, including normalized search text and reserved thumbnail and native presentation bytes. Individual images are limited to 16 MiB encoded and text to 1 MiB; larger copies are skipped without displacing existing entries. Nothing is persisted. Eviction and Clear release originals and bounded native thumbnails; clearing history leaves the system clipboard alone. Turning recording off clears history and stops its polling task and shortcut registration. A thin Swift/AppKit panel owns presentation only, using system menu material and controls. Its preview pane appears only after a continuous one-second image hover; leaving the image, filtering, clearing or closing cancels the preview. Closing releases native presentation copies. With clipboard history off, the popup shrinks to New meeting (or Stop recording), Settings and Quit; clipboard controls and previews are absent. Search is visually flat until focused; typing from the history list transfers focus without losing the first character.

A 500 ms timer reads only the native pasteboard change counter until it changes. Confidential, transient and autogenerated pasteboard types are ignored, following Maccy's MIT-licensed rules. ImageIO creates a maximum 256-pixel preview on a single background worker, retaining the encoded original for copying. There is no decode queue or full-size preview cache. Native decoder working memory and the one in-flight original are temporary and separate from the retained payload budget; epoch and entry identity checks prevent cleared or evicted images from reappearing. Text search uses precomputed lowercase strings and the list renders visible rows only.

## Accessibility

GPUI publishes an AccessKit tree for every window. `vorkspace_macos::accessibility` reads the macOS Reduce Motion setting at launch and on window activation, and speaks through VoiceOver when a session finishes or needs input. Streaming output is not announced token by token; VoiceOver reads the transcript on navigation. `keyboard_reachable` in `vorkspace-ui` makes session tabs, titlebar controls, response actions, and the send button Tab stops. Contrast and text size remain app preferences, not macOS display settings.

## Cursors

On macOS the window bridge owns cursor state per window. A hit test publishes its cursor as soon as GPUI requests it, and AppKit cursor rectangles restore the stored style after a native reset. Native child views such as WebKit and video panes sit outside those rectangles, so `native_view::invalidate_parent_cursor_rects` must run whenever one moves, hides, or appears.
