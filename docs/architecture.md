# Architecture

## Desktop ownership

`crates/vorkspace-gpui` owns windows, focus, layout, input, rendering, and interactive views, on top of the smaller `vorkspace-ui`, `vorkspace-runtime`, `vorkspace-editor`, `vorkspace-model`, and `vorkspace-macos` crates. `crates/vorkspace-core` owns provider transports, persistence, filesystem/Git operations, account configuration, Bot state, and application effects. All of them execute in one desktop process; there is no separate local daemon.

A conversation admits a turn, records its submission state, starts the selected provider CLI through the core process owner, and projects streamed events into the visible transcript. Approvals and Stop remain routed through that owner. Durable receipts and revision checks distinguish accepted work from unknown or stale results. Closing or hiding a view does not mean its conversation was deleted.

The core reads and writes the desktop SQLite schema directly. Native viewport and supplementary state live in an atomically written `.gpui.json` sidecar. Bot files live under the selected data directory. History projection preserves unloaded fields and canonical provider session IDs; conflicting writes fail instead of replacing newer state. [Data continuity](data-storage.md) explains historical-data reads.

## Rendering and history work

Indexed histories are projected one source block at a time, so loading display rows does not retain a second complete parsed transcript. Durable tool payloads remain in storage; display metadata excludes large output fields. Preference-only writes do not reconstruct historical turn receipts.

Active standalone indexed Bot chats initially retain the newest ten turns when older indexed history exists. Older pages load off the UI thread, retain the reading anchor, and carry global row offsets for saved-search reveal. A page cursor is tied to the table owner, block contents and positions, and turn boundaries in one SQLite snapshot; a changed snapshot restores the complete history, while a transient failure leaves the cursor available for retry. Transcript mutations and Bot execution restore the complete history first. Page-relative core writes independently validate the snapshot in the merge transaction, preserve unloaded blocks, and allow appends only through the newest page; they invalidate complete-history readers' write guards. The page API scans the full indexed history to validate the snapshot and calculate row offsets, so it bounds retained page rows but not read or projection work. Blob, ordinary and remote histories use their existing loading paths.

Streaming persistence writes changed blocks against a guarded durable revision. Ordered history rows separate large immutable payloads from frequently updated session metadata. The desktop and remote host each own their database transactions, including submission receipts; a GUI projection cannot replace unloaded fields. See [incremental history writes](data-storage.md#incremental-history-writes).

Bot card refreshes use an application-owned persistence worker. Admission coalesces each card without taking the database lock; the worker compares the captured card with its durable block by ID and changes only that metadata. It preserves external references, opaque fields, message boundaries and later history. Warm revision guards advance only across this owner’s commit. Fixed-size card-content guards independently reject stale card rows even after subsequent provider tail saves, until authoritative history reload. Cold digest guards retain only the owning blocks changed locally until the next history load or save, so a provider tail save can validate those exact changes without accepting external edits or stale card rows. The submission generation rejects outdated fetches before admission. Successful receipts reconcile into the matching session, save version, card identity and current value even if a new submission has started. Failed or conflicting saves keep the old visible value and release admission for a later refresh. Navigation or view disposal does not cancel admitted writes. Application quit closes admission and awaits draining within GPUI's existing 200 ms asynchronous cleanup budget; neither the quit callback nor worker-owner destruction joins a storage-blocked thread. Process exit before commit can lose an unpublished cosmetic refresh intent; the previous durable value survives and can be refreshed on the next launch.

A transcript view owns one elapsed-time task while it is visible and streaming. Terminal grids stay current when hidden; repaint-only signals are coalesced before they reach the UI queue, while ordered PTY, clipboard, and exit effects are preserved. Editor analysis shares the immutable Git baseline until a Git refresh replaces it.

Bot chats keep their configured face and name in a fixed overlay within the transcript viewport. The existing conversation status drives idle, working and attention states, with attention taking precedence. The header shares the avatar image cache but has no pointer-tracking input. Each avatar pose reports when it next changes, and the owning view is woken only then. Idle life is a sparse choreography on a window-wide 4 s beat: on some beats a Bot glances to a new look or blinks, moving for at most 300 ms on a shared 33 ms frame grid, and then holds its pose without intermediate frames until the next beat that changes it. Any number of idle avatars, across views, therefore share at most about a dozen frames per beat. Sidebar gaze keeps cursor state per window and invalidates its rendering owner when the pointer enters, moves within, or leaves the rail; the settings preview follows pointer events and blinks on the same beats. Visible working and attention avatars tick on the same frame grid. Each window and rendering owner keeps only its earliest pending wake; a sooner wake cancels and supersedes a later one. Avatar, selection-pill and swatch images live in byte-budgeted least-recently-used caches. Evicted images remain pinned while a retained view still references them. Once no scene uses an image, its atlas tiles are released across windows; visible images may temporarily exceed the cache budget. On macOS, paired native group markers fade transcript content around the face back to the already-rendered background, preserving its colors, texture and transparency. The radial feather composes with the transcript's edge fade and stays outside composer and attention controls. Decoration does not intercept chat input, and hidden or clipped content and inactive windows suppress automatic animation frames. The empty-chat greeting contains help text rather than a second face.

In the expanded project rail, each project's running, approval-blocked and unseen finished sessions hang under it like a Git tree, ordered by creation; selecting one opens it. A project's mark is the 3×3 working grid in its colour: still while idle, and waving, through its own small cached view, while any of its sessions works; the number of working sessions sits at the row's end. Channels show the still grid in their colour. Sidebar options and General settings control the tree as they did the card. The collapsed icon rail keeps the Working card: it projects running, approval-blocked and unseen finished sessions across projects from Shell's existing session state. It appears above Subscriptions when at least one session qualifies and opens sessions through the normal navigation owner. Sidebar options and General settings retain its visibility preferences. The card initially shows four sessions, with an accessible More/Show less disclosure into a height-bounded virtual list. Each row shows the project-marked title, latest actual tool or approval/completion status, and provider/project/duration metadata. Runtime tool events publish a bounded label through a dedicated conversation notification; ordinary tokens and tool output do not rebuild session discovery. Remote revision projections update that receipt on their worker, and a missing tool falls back to Working. Elapsed-time updates stay within the card's presentation; those ticks do not load history or rebuild the session snapshot. The timer stops when the card cannot display elapsed time. The card observes window bounds and preserves its top session across row reordering and compact-layout changes. Navigation shares the upper rail scroller so short windows retain access to the card disclosure, resources, subscriptions and Settings.

The project rail selects one page at a time. Search, connectors, Notes, Automations, To-dos, Bots and, when enabled, Channels are sidebar pages: they fill the main pane without a title strip and are never saved as tabs. Only a project shows a strip, holding its session and terminal tabs; page tabs saved by older versions are dropped on restore. The rail's rows and the main pane read as one surface. `liquid.rs` paints a pill for the hovered and the selected row, joined to the pane's left edge by 6px concave corners, beneath the rail's rows and clipped with their scroller; the rail's 1px divider runs down the pane edge and around each pill. The divider also follows the pane's rounded corners, except beside the icon rail, whose navigation overhangs the top one. A project's sessions are indented under it, and so are their pills. The title bar's tabs use the same surface turned on its side: hovered and active tabs' pills rise out of the line beneath the strip, which runs around them, and tab plates have no fill of their own; the **+** gets a short pill. A working session's grid, in its tab and in the Sessions sidebar, takes its project's colour. While the right-hand sidebar is open its header holds the project's diff stat and file search, and the title bar's corner no longer repeats them. The rail's footer is a thin sidebar-options row, whose menu opens upward, above Settings; it opens no pane, so it has an ordinary hover rather than a pill. Sessions, Explorer and Changes sit between the rail and the pane by default; General settings' **Switch sidebar to right side** moves them to the window's right edge. Their separator, resize and the tab strip's lead follow the side, and whichever surface meets the rail has rounded corners that the dividers follow. Bot pages have no file search. Every project and Bot has a very simple to-do board (`todos.rs`) with To do, In progress and Done columns, stored by board key in `todo_items`: a project's is the fourth tab beside Sessions, Explorer and Changes, a Bot's is a tab in its details, and the To-dos page shows a personal board or any project's or Bot's from a dropdown, with the columns side by side. Items are added from the field above the columns; clicking an item's mark moves it to the next status, dragging moves it between or within columns, and double-clicking renames it. Every open view of a board reloads after any change, including changes made through the app CLI. Sessions, Explorer, Changes and To-dos rise from the line under them like title-bar tabs. Archiving or deleting the selected project first selects another one (an only project must stay); archiving hides the project's idle tabs with it and refuses only while its conversations run or its terminals are open, and deleting, once confirmed, also closes the project's idle tabs and drops their loaded views before the usual ownership checks. Pills sit 1px inside their rows, and neighbours drop the joins that would overlap. Pills use the rail's ordinary selection fill, with hover at 70% of it, and rows have no hover background of their own. Hovering pours a pill out of the pane and leaving drains it, so a click lands on a pill that is already out and only deepens it while the previous selection drains. The section **+** buttons get short pills. Hover follows the pointer, which already repaints the rail for Bot gaze; the surface requests frames only while a pill moves, and an idle rail repaints from its cached view. Settings sections use the same surface. Search, connector, Notes, Automations, Bot and channel pages start at the window's top edge, without a title bar; a Bot's details controls stay above its right-hand panel.

Command-clicking the title strip's **+** opens and focuses a new terminal tab for the selected local project or worktree directory; a plain click and ⌘T open a session. `shell/terminal_tabs.rs` retains one `Terminal` entity per stable terminal-tab ID, independently of its starting directory and the project's dock entities. Multiple tabs in the same directory have separate shells, output and close ownership; clicking an existing title tab selects that exact shell. Selecting another tab hides the grid without terminating its PTY or changing its cwd. Terminal tabs share title-tab selection, drag order, close menus, and workspace persistence; only identity and starting cwd are saved, with a fresh shell created on first selection after restart. Legacy cwd-only saved tabs acquire IDs before order deduplication, with scope focus mapped to the corresponding tab. Explicit close checks the foreground process, asks before closing a running job, and releases the entity through `Terminal::drop` (PTY shutdown and Unix shell/process-group hangup). Hidden tab output updates its grid without observing or notifying Shell. Existing dock menu commands and shortcuts remain available and own separate shells.

Parked provider leases are removed under their pool lock, then destroyed after releasing it. Cancellation epochs prevent a settling cancelled lease from reappearing after its binding is invalidated.

Provider transports admit encoded output before growing their buffers. A single encoded provider event frame is limited to 128 MiB; each transport shares a 256 MiB allocation budget across frames being read, queued, and processed, with at most 16 queued frames. A full budget applies backpressure; an oversized frame fails explicitly instead of being truncated. Closing the receiver wakes blocked producers before their threads are joined. These limits cover encoded transport buffers, not the provider subprocess or parsed conversation state.

Interface scale is limited to 60%–160% and uses a per-window GPUI transform, separate from display DPI. The window maps platform input and text-input geometry to the same logical layout used for rendering and accessibility. Native HTML and video hosts convert their clipped bounds at the platform boundary; changing scale invalidates cached paint geometry.

## JavaScript boundaries

- Editor analysis and formatting run committed bundles in bounded QuickJS interpreters. Their time limits count the interpreter thread's CPU time, so a busy machine cannot interrupt them. Rust owns files, edits, and saves.
- Vox runs a Rust controller that owns its Codex app-server child, bounded tool receipts, saved conversation identity, memory, and shutdown. An ephemeral WebKit WebRTC page handles microphone and audio only. Window-scoped GPUI handlers admit actions through existing session and Bot owners.
- Claude sessions routed through Copilot use a Rust loopback gateway. The supervised Claude process owns its gateway across parked turns; terminating that process releases the listener and connected clients. The remote Node host retains its JavaScript gateway. Other provider transports remain Rust-owned local CLI processes.
- The remote Node host owns its own database and provider processes. SSH carries authenticated RPC through a private forward; local windows consume revisioned remote snapshots.

JavaScript is maintained directly under `host/` and `embedded/`. No browser frontend or TypeScript compilation step is part of the application build.

## Platform services

GPUI renders the desktop. WebKit is limited to Vox and sandboxed HTML previews. Sparkle can verify and install explicitly configured macOS updates.

Bots are opened inside the main workspace. The macOS menu bar opens clipboard history, also available with ⌘⇧C. General settings control the icon and contain a Clipboard group between Workspace and About. Quick Composer, Settings and Quit remain available in the clipboard menu.

Clipboard history has one process-local owner with at most 50 entries and a 64 MiB retained payload budget, including normalized search text and reserved thumbnail and native presentation bytes. Individual images are limited to 16 MiB encoded and text to 1 MiB; larger copies are skipped without displacing existing entries. Nothing is persisted. Eviction and Clear release originals and bounded native thumbnails; clearing history leaves the system clipboard alone. Turning recording off clears history and stops its polling task and shortcut registration. A thin Swift/AppKit panel owns presentation only, using system menu material and controls. Its preview pane appears only after a continuous one-second image hover; leaving the image, filtering, clearing or closing cancels the preview. Closing releases native presentation copies. With recording off, the popup shrinks to Settings, Quick Composer and Quit; clipboard controls and previews are absent.

A 500 ms timer reads only the native pasteboard change counter until it changes. Confidential, transient and autogenerated pasteboard types are ignored, following Maccy's MIT-licensed rules. ImageIO creates a maximum 256-pixel preview on a single background worker, retaining the encoded original for copying. There is no decode queue or full-size preview cache. Native decoder working memory and the one in-flight original are temporary and separate from the retained payload budget; epoch and entry identity checks prevent cleared or evicted images from reappearing. Text search uses precomputed lowercase strings and the list renders visible rows only.

## Accessibility

GPUI publishes an AccessKit tree for every window. `vorkspace_macos::accessibility` reads the macOS Reduce Motion setting at launch and on window activation, and speaks through VoiceOver when a session finishes or needs input. Streaming output is not announced token by token; VoiceOver reads the transcript on navigation. `keyboard_reachable` in `vorkspace-ui` makes session tabs, titlebar controls, response actions, and the send button Tab stops. Contrast and text size remain app preferences, not macOS display settings.

## Cursors

On macOS the window bridge owns cursor state per window. A hit test publishes its cursor as soon as GPUI requests it, and AppKit cursor rectangles restore the stored style after a native reset. Native child views such as WebKit and video panes sit outside those rectangles, so `native_view::invalidate_parent_cursor_rects` must run whenever one moves, hides, or appears.
